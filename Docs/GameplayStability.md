# 플레이 흐름 안정화 — 2026-10-28

## 적용 내용

- F9의 실행 중 부분 불러오기를 제거했다. 플레이어/인벤토리만 과거로 되돌리면 즉시 저장되는 상자/설치물과 섞여 아이템 복제가 가능하기 때문이다. `GameSaveManager.LoadGame`과 `SaveManager.TryLoadGame`도 초기 복구 후 반복 호출을 차단한다. F5 저장과 메인 메뉴의 이어하기는 유지한다. 과거 시점의 월드 전체 체크포인트 복원 기능을 추가한 것은 아니다.
- HP 0 이하인 플레이어 저장을 읽으면 성장/장비를 복구한 뒤 기존 부활 함수를 사용한다. 스폰 위치에서 최대 HP/MP 절반과 부활 무적으로 시작하며 FSM은 Idle로 돌아간다.
- `ChunkModel`이 스폰 위치와 넥서스 주변의 고정 청크 집합을 관리한다. 각 위치에 2셀 여유를 두어 경계 반대쪽 바닥도 포함한다. 기본 위치/청크 크기에서는 원점 주변 4개 청크다. `ChunkPresenter`가 시작 시 먼저 생성하며 이후 생성/제거 판단에서도 항상 유지한다. 다른 지역의 프레임 분산 스트리밍은 유지한다. 초기에 고정 구역을 동기 생성하므로 초기 로딩 비용은 늘 수 있다.
- F10 삭제는 에디터에서만 동작하고 실제 삭제 전에 확인창을 표시한다. 빌드에서는 단축키와 삭제 메서드의 실제 삭제 코드가 제외된다. 메인 메뉴의 새로하기는 기존대로 기록을 초기화한다.
- GameOverScene에 GameOverView와 GameOverPresenter를 연결했다. 화면 내용/중복 이동 상태는 GameOverModel에 둔다. 기존 DungGeunMo 폰트와 런타임 uGUI를 사용하고, 메인 메뉴/종료 버튼과 ESC 복귀를 제공한다. 화면 오브젝트는 Play 시 Canvas 아래에 생성된다.
- 넥서스 파괴 시 진행 저장을 시도하고 UI/일시정지를 초기화한 뒤 게임 오버 씬으로 이동한다. 게임 오버는 저장 삭제를 뜻하지 않는다. 새로하기/이어하기 선택은 메인 메뉴에서 한다. 습격 활성화 설정은 변경하지 않았다.

## 확인 결과와 범위

- Unity Roslyn을 통한 현재 게임 스크립트 컴파일 통과.
- 같은 참조를 사용하되 UNITY_EDITOR 심볼을 제거한 코드 컴파일 통과. 실제 Windows 플레이어 빌드 검증은 아님.
- 실제 ChunkModel/GameOverModel을 Unity API 대체 타입과 함께 실행하여 좌표/상태 검사 60개 통과: 기본 고정 청크 수, 먼 위치에서 유지, 일반 청크 제거 조건, 중복 생성 요청 방지, 버튼 중복 실행 차단 등. 실제 Unity 물리/렌더링 검사는 아님.

## Play Mode 확인 항목

1. F5 저장 후 상자에 아이템을 옮기고 F9를 누른다. 인벤토리가 과거 상태로 되돌아가지 않아야 한다. 메인 메뉴로 나갔다 이어하기 하면 현재 이동 결과가 유지되어야 한다.
2. 사망 직후 부활 전에 F5 저장하고 종료한 다음 이어하기 한다. HP 0으로 멈추지 않고 스폰 위치에서 부활해야 한다. 실험은 보관한 테스트 저장으로 한다.
3. 원점에서 충분히 멀리 이동한다. 스폰/넥서스 주변 고정 청크가 남아 있는지 확인하고 죽어서 부활한다. 바닥이 이미 존재해야 한다.
4. 에디터에서 F10 후 취소하면 기록과 씬이 그대로여야 한다. 삭제 확인 테스트는 필요 없는 테스트 저장에서만 한다. 빌드에서는 F10에 반응하지 않아야 한다.
5. NexusPresenter의 테스트 넥서스 파괴를 실행한다. 게임 오버 화면, 한국어, 마우스/키보드 버튼 입력을 확인한다. 메인 메뉴 복귀 후 새로하기/이어하기가 일시정지 상태로 시작하지 않아야 한다.

분리된 저장 파일 전체를 하나의 원자적 체크포인트로 만드는 작업과 강제 종료 중 저장 일관성 보장은 이번 범위에 포함하지 않는다.
