# 청크 전환 끊김 완화 — 2026-10-28

## 변경

- 기본 생성/제거 시간 예산을 4ms에서 2ms로 조정했다. System_Manager 프리팹에도 적용했다.
- 생성은 프레임당 최대 32셀, 제거는 최대 32개 루트 자식 오브젝트로 제한한다. 실제 시간 예산에 먼저 도달하면 더 일찍 양보한다. 한 오브젝트의 Instantiate/콜백 자체가 오래 걸리거나 Unity가 나중에 물리/렌더 처리를 수행하면 총 프레임 시간이 2ms로 제한되는 것은 아니다.
- 제거는 청크 전체를 한 프레임에 풀로 반환하던 방식에서 오브젝트 단위 코루틴으로 바꿨다. 자식 배열 복사와 일괄 DetachChildren도 제거했다. 풀 반환 전에 각 자식의 부모를 분리하여 청크 루트 파괴 시 풀의 오브젝트가 함께 파괴되지 않게 한다.
- 플레이어가 현재 밟는 청크 요청은 제거 대기열보다 먼저 처리한다. 새 생성 요청은 가까운 청크부터 등록한다. 청크 생성 완료 후 다음 청크를 같은 프레임에 연속 생성하지 않는다.
- 빈번한 청크 시작/완료 Debug.Log를 제거했다. 오류/경고와 초기화 로그는 유지한다.
- 첫 NavMesh 베이킹도 UpdateNavMesh의 비동기 경로로 변경했다. 이전 데이터는 첫 결과가 준비될 때까지 유지하고 새 런타임 데이터로 교체한다. 이후에는 같은 데이터를 갱신하며 공유 에셋은 수정하지 않는다.
- NavMesh 갱신 시작 간격은 최소 0.75초다. 연속 요청은 0.35초 동안 모으되 첫 요청 후 1초가 넘도록 계속 미루지 않는다. 초기 buildDelay와 이미 진행 중인 베이킹 시간은 별도다. 새 청크의 길찾기 반영이 즉시는 아닐 수 있다.
- 씬 전환으로 파괴된 풀 참조를 다시 꺼내는 경우 건너뛰도록 보완했다.
- 스폰/넥서스 고정 청크 및 초기 바닥 동기 생성은 유지한다. 초기 진입 로딩과 플레이 중 스트리밍은 별도다.

## 측정

컴파일과 diff 검사는 통과했다. 실제 프레임 타임 개선 수치는 아직 측정하지 않았다.

Unity Profiler의 CPU Timeline에서 다음 마커를 확인할 수 있다.

- `OutPost.Chunk.GenerateCell`: 셀 생성과 초기화
- `OutPost.Chunk.ReleaseObject`: 계층 분리, 비활성화 및 풀 반환
- `OutPost.NavMesh.CollectAndSchedule`: 물리 동기화와 NavMesh 지형 수집/비동기 요청

같은 저장 위치와 이동 경로에서 청크 경계를 여러 번 통과하며 최대 프레임 시간과 위 마커를 비교한다. 첫 탐험과 이미 방문한 구역의 왕복은 풀 재사용 여부가 다르므로 따로 비교한다. 청크 생성/제거 후 몬스터 추적, 블록 파괴 후 경로 갱신, 먼 거리 부활, 메인 메뉴 복귀 후 이어하기도 확인한다.

Unity NavMeshSurface.UpdateNavMesh는 베이킹은 비동기지만 CollectSources는 호출 프레임에서 실행한다. 해당 마커가 계속 큰 스파이크를 차지한다면 다음 단계는 청크별 소스 캐시 또는 청크별 NavMesh 분리다. 이번 변경만으로 모든 끊김이 없어졌다고 판단하지 않는다.
