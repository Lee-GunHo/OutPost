## 자동 적용 및 설정

- 기존 몬스터 프리팹 수정 없이 `MonsterCombatPresenter.Start()`에서 씬에 `Monster AI research` 오브젝트를 만든다.
- 이 오브젝트의 `MonsterAIExperimentModel`에서 설정한다.
  - `Learning Mode = Training`: 자연 생성 개체의 경험 수집 및 학습.
  - `Baseline`: 학습 배율 1, 학습 데이터 변경 없음.
  - `Frozen`: 저장된 학습값 사용, 추가 학습 없음. 비교 실험용.
  - `Cooperation Enabled`: 진형·역할·공동 공격 시작 제한을 함께 켜거나 끈다. 충돌 회피/겹침 완화는 양쪽 모두 유지한다.
  - `Waves Use Learned Policy`: 기본 false. true면 웨이브 등 자연 생성으로 표시되지 않은 일반 몬스터도 학습값을 사용할 수 있다. 이들은 경험을 갱신하지 않는다.
  - `Write Csv`: 기본 true. CSV와 정책 스냅샷 기록.
  - `Show Overlay`: 기본 false. 버전·모드·기록 수를 개발용 화면에 표시.
- 다른 기본 설정으로 시작하려면 게임씬의 빈 오브젝트에 `MonsterLearningPresenter`를 미리 붙이고 자동 추가된 Model에서 설정한다. 같은 씬에 하나만 둔다.
- `MonsterSpawner`가 생성 개체를 `MarkNaturalSpawn(prefab.name)`으로 표시한다. 다른 자연 스포너를 추가한다면 동일 호출을 연결해야 한다.
- 보스는 적용 대상이 아니다.
- 개체는 생성 후 Start 시점의 학습 스냅샷을 사용한다. 경험은 계속 공유 기억에 쌓이지만 살아 있는 모든 몬스터의 행동이 매번 즉시 바뀌지는 않는다. 새 개체가 새 기억을 사용한다. 모드 변경/로드 시 기존 개체도 다음 선택 전에 스냅샷을 갱신한다.

## A. 개별 몬스터 학습 AI

| 구분 | 현재 구현 |
| --- | --- |
| 목적 | 플레이어에게 실제 피해를 줄 수 있었던 공격의 선택 비중을 해당 상황에서 점진적으로 높임 |
| 학습 단위 | 몬스터 프리팹 이름 × 상황 구간 × 공격 종류. 개체의 기억을 종별 공유 기억으로 누적 |
| 학습 입력 | 거리 구간(≤1.8 / ≤3.75 / 그 이상), 자신 체력(≤35% / 그 이상), 플레이어 상태(일반 / 공격 / 대시), 실제 공격 결과 |
| 기존 규칙 입력 | 공격 사거리·시야·활성화 여부·쿨다운, 최근 피격, 직전 공격, 자신의 체력, 배정 역할 |
| 추가 기록만 하는 입력 | 플레이어 체력 비율. 현재 학습 키나 협동 역할 점수에는 사용하지 않음 |
| 출력 | 합법적인 근접/투사체/원형/돌진 공격의 선택 가중치와 정규화된 선택 확률 |
| 실행 | 가중 확률 추첨 후 기존 FSM/공격 실행기에 전달. 최고 점수 행동만 고르는 방식이 아님 |
| 학습하지 않는 행동 | 추적, 거리 유지, 후퇴, 퇴각은 현재 규칙을 유지 |

흐름:

```text
거리·체력·플레이어 상태 → 상황 키
사거리·쿨다운·시야 → 가능한 공격 목록
기존 Utility 가중치 × 생성 시 학습 배율 → 확률 추첨 → 기존 공격 실행
실제 HP 감소/실패 결과 → 공유 기억 갱신 → 저장 → 이후 생성 몬스터
```

수식(현재 구현):

```text
피해를 줌: reward = +1
빗나감 또는 플레이어 접촉 후 실제 피해 없음: reward = -0.25
meanReward += 0.08 × (reward - meanReward)
confidence = attemptCount / (attemptCount + 12)
multiplier = clamp(1 + meanReward × confidence, 0.65, 1.8)
finalWeight = 기존 상황/역할 가중치 × multiplier
probability = finalWeight / 가능한 공격들의 finalWeight 합
```

초기 표본이 적으면 기본 행동에 가깝게 유지한다. 일정 확률을 0으로 만들지 않으며 실패가 누적된 공격도 재시도할 수 있다. 공격의 사거리나 쿨다운 제한을 학습으로 무시하지 않는다. 피해량 자체를 늘리거나 몬스터 스탯을 학습으로 강화하지 않는다.

이는 **Utility 선택기에 상황별 결과 평균을 결합한 가벼운 온라인 가중치 적응**이다. 선택한 공격 결과만 갱신하는 bandit 형태이지만 신경망, Q-Learning, 장기 보상 최적화 또는 완전한 플레이어 행동 예측 모델은 아니다.

대시 상태는 선택 시점의 관측이다. 대시 종료 후 경과 시간, 반격 성공률, 장기 회피 궤적은 아직 별도 학습하지 않는다. 실제 피해가 없는 접촉은 무적·방어 등 원인을 세분화하지 않아, 플레이어가 회피했다고 단정할 수 없다.

## 공격 결과 판정

| 결과 | 의미 | 가중치 갱신 |
| --- | --- | --- |
| Hit | Player HP가 실제 감소 | +1 |
| Miss | 실행된 공격이 플레이어에게 닿지 않고 종료 | -0.25 |
| NoDamageContact | 플레이어에 닿았으나 실제 HP 감소 없음 | -0.25 |
| Blocked | 장애물/다른 몬스터/내비게이션 경계 등에 막힘 | 제외 |
| Cancelled | 발사/공격 실행 전 피격·사망 등으로 취소 | 제외 |
| Interrupted | 실행 중 강제 중단·투사체 제거 | 제외 |
| TargetLost / OtherTarget | 타깃 소실 또는 플레이어 외 대상에 종료 | 제외 |

- 이전 `AttackFinished(kind, released)`는 명중 신호가 아니므로 학습 성공 판정으로 사용하지 않는다.
- `actionId`로 공격 한 번을 식별하고 결과는 한 번만 확정한다.
- 독·출혈의 이후 틱 피해는 이번 직접 공격 보상/피해량에 포함하지 않는다.
- 몬스터의 생존 여부는 학습 조건이 아니다. 사망한 몬스터가 이미 발사한 투사체도 적중/종료 때 원래 공격의 기록을 확정한다.
- 씬 종료·로드로 잘린 관측을 실패로 학습시키지 않는다. 로드/초기화 이전의 진행 중 관측은 무효화한다.
- Nexus만 공격하는 관측은 개별 플레이어 학습에서 제외한다.

## B. 협동 몬스터 진형 AI

| 구분 | 현재 구현 |
| --- | --- |
| 목적 | 플레이어를 상대하는 일반 몬스터들의 역할·위치를 분배 |
| 입력 | 인원·위치·거리·체력 비율·최대 체력·속도·엄호 필요 여부·원거리/돌진 사용 가능 여부 |
| 판단 | 규칙과 역할 적합도. 기존 전방에 유지 가산점을 주어 잦은 교대 방지 |
| 출력 | Solo / Pressure / Support / Flanker, 인원수, 목표 각도; 역할에 따른 거리와 공격 비중 |
| 변화 시점 | 합류/이탈 및 엄호 필요 상태 변화 때 즉시 재계산, 그 외 약 2초마다 재평가 |
| 학습 | 하지 않음. 학습 JSON은 진형/역할 평가식을 변경하지 않음 |

- 1마리: Solo.
- 2마리: 전방 + 지원 또는 측면. 원거리 능력이 없고 건강한 후속 개체를 억지로 원거리 지원으로 지정하지 않는다.
- 3마리: 전방 + 지원/측면을 분배하고 플레이어 주위에 세 각도 배치.
- 4마리 이상: 전방과 여러 지원/측면 역할, 서로 다른 각도를 배정.
- 전방 적합도: 부상/후퇴 필요 감점, 체력 비율·최대 체력·속도 가점, 거리 감점. 기존의 건강한 전방 역할에는 유지 가산점.
- 지원 적합도: 엄호 필요·원거리 능력 가점. 돌진 가능·빠른 개체는 상대적으로 측면에 남기기 쉬움.
- 낮은 체력의 전방은 다른 개체로 교체될 수 있다. 모든 몬스터가 약하면 상대적으로 적합한 전방을 고르며, 팀 전체 퇴각을 명령하는 단계는 아직 없다.
- 기존 전방 이동속도 1.25배, 역할별 공격 가중치, 후속 개체의 측면 이동, 공동 공격 시작 간격은 유지한다. 후방 쿨다운 감소 버프는 추가하지 않았다.
- 경로가 막히면 개별 추적/공격으로 돌아가는 기존 처리를 유지한다.
- 몬스터의 모든 스탯과 공격 설정이 같으면 장단점에 따른 차이도 작다. 프리팹의 수치/공격 활성화를 다르게 설정해야 종별 차이가 명확하게 보인다.

## 저장 및 확인 자료

학습 저장: `Application.persistentDataPath/monster_learning.json`

- 이어하기 및 재실행 시 읽는다.
- 학습 변경은 10초 간격 및 게임 저장·앱 일시정지·종료 때 저장한다.
- 새로하기/전체 저장 삭제에서 학습 JSON 및 임시 파일을 함께 제거하고 메모리도 초기화한다.
- 손상된 학습 파일은 경고 후 기본 행동을 사용하며 해당 파일을 자동으로 덮어쓰지 않는다.
- 실험 자료는 진행 저장과 분리하여 새로하기에서도 유지한다.

자료 폴더: `Application.persistentDataPath/MonsterAIResearch/<UTC시각_GUID>/`

| 파일 | 내용 |
| --- | --- |
| initial_policy.json | 세션 시작 시 저장된 정책 |
| policy_vN.json | 종료 또는 Presenter의 `Export Current Policy Snapshot` 메뉴에서 내보낸 기억 |
| actions.csv | 공격별 battleId/actionId, 타입, 역할, 모드, 상황, 합법 행동 목록, 선택 확률, 사용 정책 버전, 결과, 실제 피해 |
| learning_updates.csv | 선택 공격의 누적 시도/명중 수, 보상, 이전/이후 학습 배율, 갱신 버전 |
| battles.csv | 전투 시간, 인원, HP, 몬스터 피격 합계, 종료 사유, 포위/겹침 시간, 역할 교대 수 |
| participants.csv | 전투 참여/이탈 시간과 Killed/Escaped/Disengaged 등 사유 |
| formations.csv | 그룹, 인원, 진형 이름, 역할, 각도, 재배치 이유 |
| battle_configs.csv | 시작 시 플레이어 레벨/스탯/위치, 저장된 월드 시드, 정책 버전 |
| participant_configs.csv | 타입, 자연 생성 여부, 기본 체력/공격력/속도, 가능한 특수공격 |

모든 CSV는 10초 간격으로 디스크에 flush한다. `SaveNow()` 호출이나 정상 종료에서도 flush한다. 파일이 아직 없으면 해당 사건이 아직 발생하지 않았을 수 있다.

실험 설정을 바꾸거나 F9로 로드하면 진행 중 전투는 별도 종료 사유로 분리한다. 분석 도구는 이런 중단 전투를 완료 전투 평균에서 제외한다.

## 측정 정의와 한계

- 전투 시작: 일반 몬스터가 플레이어를 대상으로 교전하거나 공격/피격 기록이 시작된 때.
- 종료: 플레이어 사망 또는 참여자 교전이 5초간 끊긴 때. 종료 대기 5초는 전투 지속 시간에서 제외한다.
- 개인 참여 시간: 추적/전투 진입부터 사망·탈출·교전 해제까지. `meanEngagedSeconds`는 엄밀한 생물학적 생존 시간과 다르다. 사망한 개체만의 `meanTimeToDeathAmongKilled`도 따로 출력하며 생존자 편향에 주의한다.
- 실제 피해 명중률: 실제 피해가 있었던 공격 / 실행 후 결과가 확정된 공격. 분석 분모에는 Blocked가 포함되고 Cancelled/Interrupted/TargetLost는 제외한다. 학습 보상의 분모와 구분한다.
- 조건부 선택률: 그 공격이 가능한 선택 시점 중 실제 선택된 비율. 전체 선택 비율만 보면 사거리/쿨다운 차이를 학습으로 오해할 수 있다.
- 겹침 시간: 0.2초 간격으로 측정, 몸 반경 합의 90%보다 가까운 쌍이 하나라도 있는 시간을 누적. 쌍마다 중복 합산하지 않는다. NavMesh 회피와 분리 보정은 협동 OFF에서도 유지한다.
- 포위: 6 유닛 안에 최소 3마리, 플레이어 기준 인접 몬스터 각도 간 최대 빈 구간이 180도 이하. 성립 시간을 누적하고 비성립→성립 횟수를 센다. 공격 명중 성공과는 다르다.
- 역할 교대: 이미 Solo가 아닌 역할에서 다른 비Solo 역할로 변경된 개체 수. 한 번의 전방/지원 맞교대는 두 개체 변경으로 셀 수 있다.
- 일반 몬스터가 플레이어에게 준 직접 피해만 attack CSV를 battleId로 합산한다. 보스/환경/독 틱 피해는 포함하지 않는다. HP 시작-종료 차이로 피해량을 대신 계산하지 않는다.
- 몬스터 피격 합계는 `MonsterPresenter.TakeDamage`의 HP 차이다. 현재 호출 경로를 기록하며 공격자 종류를 따로 식별하지 않는다.
- 측정은 단일 플레이어 전제이며 표본 간격에 따른 근사치다. 저장된 월드 시드만으로 런타임 물리·행동 난수까지 동일하게 재현하지는 못한다.
- 측면 공격의 실제 입사각, 공격 방향 다양성, 후퇴 후 반격 성공률, 퇴각 시도 대비 성공률, 팀 진형 붕괴 원인은 아직 자동 집계하지 않는다. Escaped 건수는 확인 가능하다.

## 비교 실험

| 조건 | Learning Mode | Cooperation |
| --- | --- | --- |
| A | Baseline | false |
| B | Frozen | false |
| C | Baseline | true |
| D | Frozen | true |

- 실제 게임에서 Training으로 경험을 쌓고 JSON을 내보낸 뒤 평가에서는 Frozen을 사용한다.
- A↔B는 개별 학습, A↔C는 협동 전체 효과, C↔D는 협동 상태에서 학습의 추가 효과를 비교한다.
- 맵/장애물, 플레이어 장비·레벨·HP·행동 전략, 몬스터 종류·수·스탯·배치, 정책 스냅샷을 맞춘다. 같은 새로하기 버튼으로 A/B를 만들면 시드와 학습 파일이 초기화되므로 비교 조건이 달라진다.
- 정책 스냅샷과 진행 저장을 보관한 뒤 별도 동일 조건 실험을 수행한다. 현재 도구가 자동으로 플레이를 재연하지는 않는다.
- 협동 ON에는 기존 이동속도/역할 공격 비중/동시 공격 제한도 포함된다. 이 비교는 진형 알고리즘 단독 효과가 아니라 협동 기능 묶음의 효과다.
- 비교는 자연 생성 몬스터만으로 시작한다. 웨이브·보스를 섞으면 전투별 결과 해석이 어려워진다.
- 전략별로 반복 측정하고 시도 횟수를 함께 제시한다. 통계적으로 충분한지 확인하기 전 평균 증가를 확정적 학습 효과라고 표현하지 않는다. 대기나 무의미한 생존 시간 증가도 자동으로 좋은 결과는 아니다.

분석 실행(프로젝트 루트):

```powershell
python Tools/MonsterAI/analyze.py "<세션A 폴더>" "<세션B 폴더>" --output "<보고서 폴더>"
```

생성물: `attacks_summary.csv`, `attacks_by_context.csv`, `battles_enriched.csv`, 완료 전투가 있으면 `comparison.csv`, 학습 기록이 있으면 `learning_weights.csv`. Python에 matplotlib이 설치되어 있으면 `attacks.png`, `learning_weights.png`도 만든다. 없는 표본은 0%로 꾸미지 않고 비워 둔다. 그래프는 현재 단순 요약이며 신뢰구간/유의성 검정은 포함하지 않는다.

| 발표 지표 | 학습 전/협동 OFF | 학습 후/협동 ON | 변화 |
| --- | --- | --- | --- |
| 완료 전투 수 | 측정 필요 | 측정 필요 | — |

시연 영상에는 동일한 플레이어 행동, 네 가지 실험 설정, 정책 버전과 동일 상황의 선택 비율 변화를 함께 보여준다. 학습 파일은 신경망 모델이 아닌 JSON 가중치/경험 파일이다.

## 모델 선택과 게임 설정

현재는 마감 전 범위를 고려해 Utility + 결과 기반 가중치 조정을 구현했다. 상황별 선택과 관측 보상을 확장하면 Contextual Bandit 정책으로 발전시킬 수 있다. Q-Learning은 후퇴 후 반격 같은 긴 행동 결과를 다루는 후속 후보지만 상태 수와 보상 설계가 추가된다. ML-Agents 학습 환경 구축은 이번 범위에 없으며, ONNX는 모델 교환/실행 형식이지 학습 방법 자체가 아니다.

세계관은 **군체 기억**이 현재 저장 방식에 가장 잘 맞는다. 죽은 개체를 포함한 전투 경험이 종별 기억에 축적되고 이후 개체가 이를 이어받는다. 생존/퇴각 개체만 정보를 전달한다고 설정하면 실제 구현과 어긋난다. 던전 코어가 군체 기억을 수집한다는 연출을 붙일 수 있으나 아직 연출/설정 UI는 없다.

## 파일과 검증 범위

- Model: `MonsterLearningModel`, `MonsterAIExperimentModel`, `MonsterCombatTelemetryModel`, `MonsterEncounterTelemetryModel`.
- Presenter: `MonsterLearningPresenter`(학습/저장/로그), `MonsterCombatTelemetryPresenter`(전투 관측), 기존 Combat/Projectile/Behavior/Squad/Spawner 연결.
- View: `MonsterLearningView`(선택적 개발 표시).
- 저장 연결: `GameSaveModel`, `GameSaveManager`. 플레이어 상태 읽기: `PlayerStateManager`.
- 순수 모델/저장 삭제 범위 검사는 `powershell -NoProfile -ExecutionPolicy Bypass -File Tools/MonsterAI/Run-ModelChecks.ps1`로 실행한다.
- 실제 Unity 게임뷰 검증, 성능 측정, 학습 효과 실험, 영상 촬영은 별도로 필요하다.

다음 우선순위는 실제 플레이에서 기록이 쌓이는지 확인 → 학습 전후 동일 조건 측정 → 가중치/프리팹 역할 튜닝 → 부족한 협동 조건·후퇴 결과 계측 확장이다.
